# Scope

## In Scope

The MVP delivers, end to end:

- Three HTTP endpoints (`POST /quotes/refresh`, `GET /quotes/:id`, `GET /quotes/latest?base=BASE&quote=QUOTE`) with the contract from `discussions/api-contract.md`.
- Whitelist of currencies (`USD`, `EUR`, `MXN`); service autogenerates all ordered pairs at startup (6 pairs for 3 currencies), excluding self-pairs.
- Postgres-backed queue (`quote_jobs`) with `FOR UPDATE SKIP LOCKED`, lease, and crash recovery.
- Background scheduler that refreshes whitelist currencies on a tick.
- Coalescing of concurrent and overlapping refresh requests via `dedup_key = sha256(UPPER(base) + ":" + UPPER(quote) + ":" + bucket_unix_seconds)`.
- One real rates provider (`apilayerProvider` — apilayer-family: currencylayer, fixer, or exchangeratesapi.io) plus a fake provider for dev and load testing.
- Token bucket protection against monthly quota exhaustion.
- Structured logging through `internal/obs`, Prometheus metrics, request-id propagation.
- Health endpoints (`/healthz`, `/readyz`).
- OpenAPI spec as the source of truth for the contract; handlers generated by `oapi-codegen`.
- Test pyramid (unit / integration / smoke load) per `discussions/testing-strategy.md`.
- Docker Compose stack: service + Postgres + Prometheus + Grafana + fake provider.
- README with build, run, configuration, and endpoints documentation.

Implementation order is in `discussions/implementation-roadmap.md`.

## Out of Scope

Each item is here for one of two reasons: **not part of MVP** (deferred to a later stage) or **not part of this service at all** (different layer, different team, or different problem entirely).

### Deferred — designed, will be implemented in a later stage

- **Classical idempotency via `Idempotency-Key` header.** Designed in `discussions/idempotency.md`. Stage 6 of the roadmap.
- **Production-on `kin-openapi` runtime validation.** MVP enables validation in dev/test only. See `discussions/openapi.md`.
- **Multi-provider fallback and circuit breaker.** Designed in `discussions/resilience.md`. Stage 6.
- **OpenTelemetry distributed tracing.** Forward-compatible with current `X-Request-Id` propagation. See `discussions/monitoring.md`.
- **Tariff-plan-specific tuning** beyond MVP defaults — `discussions/capacity.md`.
- **Property-based testing** for bucket math and dedup. See `discussions/testing-strategy.md`.
- **Load and stress testing** beyond smoke profiles. See `discussions/load-testing.md`.
- **Multi-region active-passive / active-active** deployment. See `discussions/scaling.md`.

### Not part of this service

- **AuthN/AuthZ.** Performed at the API gateway in front of the service. The HTTP layer here keeps an empty `authn` middleware slot for future zero-trust or mTLS revalidation, but does not authenticate clients itself.
- **Per-endpoint rate limiting for callers.** Done at the gateway. The token bucket in this service protects the **upstream** budget, not inbound traffic.
- **CORS, public API surface.** The service is consumed S2S by internal callers and BFF. Public exposure (if it ever happens) requires a separate API surface with its own auth, CORS, and rate-limit policy.
- **A/B testing / experimentation.** The service has no personalised behaviour to vary; rate data is objective. Rollout strategies (canary deployment, feature flags, shadow traffic for new providers) are deployment concerns and live with the deployment repo.
- **Audit logging for compliance.** Different lifecycle (longer retention, immutable, structured for regulators). If required later, it is a separate pipeline alongside operational logs.
- **Backup and restore strategy.** Deployment concern. The `quotes` table is rebuildable from the upstream within `T` seconds; `quote_jobs` may lose in-flight rows on disaster restore — clients can refresh again.
- **Cost optimisation** (reserved instances, spot pricing, query plan tuning past basic indexes). Operational concern.

### Out of scope by design

- **Historical quotes / time-series of rates.** The `quotes` table is a single-row-per-currency cache. Time-series data, if needed, lives in a different system.
- **Customer-specific quotes (with spread, markup, hedging).** This is a public-data service. Personalised quote logic belongs in the BFF or a dedicated quote-engine service.
- **Streaming protocols (WebSocket, FIX, Server-Sent Events).** The service is REST-only.
